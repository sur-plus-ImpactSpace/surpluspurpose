# Runbook — move the repository out of iCloud Drive

Status: prepared 2026-07-09, not executed yet.

## Why

The repo lives in `~/Documents/sur.plus`, and `~/Documents` is synced by iCloud Drive
("Desktop & Documents Folders"). A git repository with `node_modules` inside an iCloud
folder is a known-bad combination. It has already cost us real time:

- **iCloud duplicates broke CI.** Sync conflicts produced `node_modules 2` and
  `.pnpm-store 2` symlinks. Two of them were committed and made `next build` fail on the
  runner with `ENOENT: … stat 'apps/web/node_modules 2'`. Several red CI runs.
- **Broken module resolution.** iCloud renamed the real `node_modules` symlink, so
  `eslint`, `tsc` and `pnpm` could not resolve packages locally.
- **Stale git locks.** iCloud damaged the folder permissions ("Unable to complete iCloud
  Drive sync. Repair permissions to finish syncing."). Git left `index.lock`, `HEAD.lock`
  and `objects/maintenance.lock` behind, blocking every commit — including GitHub Desktop.
- **Sync pressure.** ~775 MB of `node_modules` (tens of thousands of tiny files) is more
  than iCloud handles gracefully.

GitHub is the backup for everything versioned. iCloud only needs the business folders
(`01_STRATEGY` … `07_SALES`), which sync fine.

> **Correction (2026-07-10, after the move).** The sentence above is only half true and
> the move exposed it: the numbered business folders are gitignored, so GitHub is *not*
> their backup — iCloud was, purely because they sat under `~/Documents`. Moving the repo
> to `~/Projekte` left ~426 MB of business plan, contracts, finances and CVs with **no
> backup at all**. Fix that before anything else: see
> [`business-folder-separation-runbook.md`](./business-folder-separation-runbook.md).

## Before you start

- [ ] Everything is committed **and pushed** (`git status` clean, no `ahead` count).
- [ ] Quit **GitHub Desktop**, **VS Code**, and any running `pnpm dev` / dev server.
- [ ] Confirm no iCloud placeholders remain (should print `0`):

```bash
find ~/Documents/sur.plus -name '*.icloud' | wc -l
```

If it prints anything but `0`, right-click the folder in Finder → **Download Now**, wait,
and re-check. Moving a folder with undownloaded placeholders loses data.

## Steps

### 1. Delete the dependency dirs and the iCloud workarounds

They are regenerated by `pnpm install`, they are the bulk of the move, and the `.nosync`
trick only existed because of iCloud.

```bash
cd ~/Documents/sur.plus
rm -rf node_modules* .pnpm-store* \
       apps/web/node_modules* \
       packages/domain/node_modules* \
       tools/node_modules*
```

### 2. Move the repo

```bash
mkdir -p ~/Projekte
mv ~/Documents/sur.plus ~/Projekte/sur.plus
```

### 3. Reinstall and verify

```bash
cd ~/Projekte/sur.plus
pnpm install
git fsck                 # object store survived the move
pnpm run ci              # lint → typecheck → build → unit tests
node tools/smoke.mjs --start
```

`git status` must be clean and `git log --oneline -1` must show the same commit as before
the move. Nothing about the remote changes — the move is local only.

### 4. Re-point the tools

- **GitHub Desktop:** the old entry now points at a missing path. Remove it
  (right-click the repository → *Remove*, **do not** tick "move to Trash"), then
  *File → Add Local Repository…* → `~/Projekte/sur.plus`.
- **VS Code / editors:** reopen from the new path.
- **Cowork:** reconnect the folder, otherwise the assistant keeps writing to the old path.
- **Netlify / CI:** nothing to do. Both build from GitHub, not from this machine.

### 5. Clean up afterwards

Once `pnpm run ci` is green from the new location, the `.nosync` ignore rules in
`.gitignore` are dead weight — but harmless. Leave them for one release cycle in case the
repo ever lands back in a synced folder, then delete this block:

```
**/node_modules.nosync/
**/.pnpm-store.nosync/
**/node_modules [0-9]
**/node_modules [0-9][0-9]
**/.pnpm-store [0-9]
**/.pnpm-store [0-9][0-9]
```

## Rollback

The move is a rename. If anything looks wrong:

```bash
mv ~/Projekte/sur.plus ~/Documents/sur.plus
```

The repository is also fully on GitHub — worst case, delete the local copy and
`git clone git@github.com:flolechner91/sur.plus.git` into `~/Projekte/`. Only the
gitignored business folders (`01_STRATEGY` … `07_SALES`, `CLAUDE.md`) are local-only,
so **copy those out first** if you ever re-clone instead of moving.

## Afterwards

Keep dev repositories out of iCloud-synced folders (`~/Documents`, `~/Desktop`).
`~/Projekte` is not synced.
